# 开发 Agent 交接

## 当前交付

此仓库只完成规划、技术边界、接口草案和验收设计。没有应用实现、go.mod、Dockerfile 或可运行发布物。初始化 Agent 不负责应用开发。

后续开发者应直接从 P0 开始，不再先写一套平行规划。

## 最少读取路径

1. [AGENTS.md](../AGENTS.md)：协作边界。
2. [计划入口](README.md)：当前阶段。
3. [范围](00-scope.md)：最新用户要求。
4. [架构](01-architecture.md)及[技术栈与内存](02-stack-and-memory.md)：实现约束。
5. 当前阶段需要时，再读接口、CWA 集成、验收和研究证据。

研究中旧的译本隔离建议已经退出首版，不应被重新实现。CWA 源码不得修改。

## 可直接发送的提示词

> 请在这个仓库接手开发。先读 AGENTS.md 和 plan/README.md，按渐进式导航读取当前阶段所需文档，从 P0 开始实现并测试。使用 Go，遵守低内存验收门槛；默认中文优先，所有书籍最终从 CWA 交付。不得修改 CWA 源码，不做译本隔离，不引入 Python 或额外服务。按阶段提交并更新进度，不停留在重写规划。真实接入缺少配置时，先完成全部可独立验证的开发，清楚列出待验收项。

## 接手后第一批动作

- 检查 Git 工作区与当前计划状态，保留其他人的改动。
- 核对依赖、工具链与上游接口，完成 P0 的有界请求和最小 MCP 互通实验。
- 记录实际选定版本后再建立项目代码。
- 在任何真实 NAS 写入或配置变更前，核对本轮用户授权范围；本交接文档本身不是生产环境部署授权。
- 把阶段结果、测试和未解决问题写在唯一进度入口，详细证据链接到对应文档。

## 每阶段交付格式

简短说明：完成的行为、验证方法和结果、实际资源数字（若已测）、仍未验证的边界、下一阶段。不要把预计内存、源码推断或模拟结果当成真实服务表现。
