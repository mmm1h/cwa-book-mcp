# 验收矩阵

只有记录了实际测试方法与结果的项目才算通过。源码阅读、函数级实验、HTTP 模拟、真实 CWA 和目标 NAS 是不同证据等级。

本页保留验收条件；实际通过项、运行版本和证据在 docs/validation.md、docs/benchmarks 和 plan/README.md。R14 由初始化提交验证，不是运行时测试。

## 资源与生命周期

门槛与场景只在 [内存预算](02-stack-and-memory.md) 定义，测试结果需要逐项对应：

- 进程 RSS 与 cgroup 指标都采集，不能用 Go heap 代替。
- 大文件用流式生成的合成数据，不把 1 GiB fixture 提交仓库或先放进内存。
- 正常传输、慢连接、body 超限、压缩炸弹式元数据、取消、管道断开都覆盖。
- 20 个控制请求突发时有背压，活跃文件传输不超过上限。
- 任务等待期间无“每任务一个永久 goroutine/定时器”的增长。
- 1,000 条历史任务存在时仍通过；保留上限生效，bbolt 文件增长可解释。
- 固定 128 MiB 容器压力测试必须完成，不以增大限制作为修复。
- race 检测单独运行，不把它的峰值与发布构建比较。

## 分层测试

| 层级 | 适用内容 | 外部凭据 |
| --- | --- | --- |
| 单元 | 搜索优先级、规范化、票据、状态迁移、幂等 | 无 |
| HTTP 集成 | 登录/CSRF、OPDS、multipart、失败响应、重定向 | 无，使用 httptest |
| 持久化/崩溃恢复 | 提交前后断点、完整文件恢复、孤儿文件清理 | 无 |
| MCP 协议 | initialize、tools/list、tools/call、错误和取消 | 无 |
| 受控端到端 | 书源替身 → 暂存 → CWA 替身 → 下载 | 无 |
| 原版 CWA 集成 | P0 尽早探测、P3 完成实际上传/转换/下载 | 独立临时书库和测试账号，无需生产凭据 |
| MCPHub/Agent | 聚合调用与本地自动上传/下载 | 测试环境配置 |
| 目标实例 | 真实版本、权限、网络和资源限制 | 操作者安全配置 |

真实书源登录和额度测试必须显式启用，不能在公共 CI 中自动消耗账号。CI 默认运行确定性的模拟测试。
