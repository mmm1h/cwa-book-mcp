# 分阶段实施计划

本页是任务分解；实现、验证与阶段状态只更新 [plan/README.md](README.md)。退出证据见 docs/validation.md 和资源报告。

## P0：优先消除依赖和集成风险

读取：scope、stack-and-memory、CWA 集成、研究证据。

- 固定可兼容的 Go、MCP SDK、bbolt、heartleo/zlib 版本，记录理由和许可证。
- 在本阶段建立最小 go.mod/go.sum 和可重复的风险验证测试，P1 在其上扩展；不要求先有完整服务才验证依赖。
- 验证只导入书源核心包能否构建，是否带入不必要的 TUI/CLI 路径。
- 用受控 HTTP 端点验证书源搜索的取消、超时、元数据响应大小和流式下载。
- 明确如何补上上游缺失的请求限制，不允许用外层超时掩盖后台泄漏。
- 对官方 SDK 做最小 Streamable HTTP 互通验证，记录协议协商结果。
- 准备小型合成 EPUB/PDF 和 CWA HTTP fixture；不得提交真实书籍或账号数据。
- 固定首版确实支持的输入/输出格式和校验办法；不把任意扩展名当作支持。
- 有容器运行条件时，使用固定版本的原版 CWA、独立临时书库和测试账号验证 OPDS/上传/格式展示；不访问现有 NAS。缺少条件时记录为集成待测，不阻塞独立开发，但须在 P3 退出前补上。
- 核对当前设计中 ready 的语义，不重新加入译本或元数据写回。

退出：依赖可构建，关键不确定点有实验结论；需要最小书源适配补丁时记录范围。没有实际 CWA 凭据也可完成本地部分。

## P1：服务、持久任务与 MCP 基础

读取：架构、接口契约、内存预算。

- 沿用 P0 的依赖基线，建立入口、配置校验、优雅退出。
- MCPHub 托管一个 stdio 进程并在同进程提供文件接口；可选 net/http 模式承载 /mcp 与文件接口，Bearer 校验覆盖 HTTP MCP 请求。
- 注册五个工具，测试中接替身；尚未实现的真实操作明确返回 NOT_IMPLEMENTED，不让生产路径返回模拟成功。
- 实现 bbolt schema_version、任务记录、request_id 幂等索引、到期索引。
- 实现单 worker、有界传输许可、背压与恢复扫描，以及非终态总寿命和取消回收。
- 建立最少量的开发命令和 CI：格式、vet、单元与有针对性的 race 测试。
- 测量最小服务空闲 RSS，尽早发现依赖预算问题。

退出：重启可恢复任务；重复请求不重复创建任务；客户端断开不取消已持久化业务任务。

## P2：CWA 读取与中文优先搜索

读取：scope、CWA 集成、接口契约。

- 实现 CWA OPDS 客户端、鉴权错误分类、有界 XML 解析。
- 实现书源搜索与候选详情适配。
- 规范语言、标题、作者、格式；所有未知字段保持未知。
- 实现中文优先的四级搜索、显式语言覆盖和有界分页。
- 绑定候选/游标与查询条件，落实 TTL、数量上限和过期错误；同一层分页不能反复返回第一页。
- 实现 get_download_url，只转发 CWA 文件。
- 为认证失败、HTML 错误页、格式缺失和重定向行为加测试。

退出：搜索规则通过验收矩阵；能通过直接 MCP 客户端验证搜索和 CWA 下载转发。此阶段不假装已完成新书入库。

## P3：书源获取、本地上传和入库核对

读取：架构、CWA 集成、文件接口契约。

- 下载到专属暂存路径，完成类型、长度及基本完整性检查。
- 实现登录/CSRF/Cookie 复用和流式 CWA 新书上传。
- 实现上传票据和单次流式 PUT，完整校验后自动入队；断开从头重传，响应丢失先查任务。
- 按部署声明的 CWA 规则核对目标格式。
- 实现 submitting/uncertain/reconciling/needs_review 等状态；不确定结果禁止自动重传。
- 实现一次必要的 CWA 文件实际验证，再写入 ready。
- 实现有限重试、账号阻塞、用户选择候选和显式恢复。
- 清理策略覆盖成功、失败、客户端中断和进程崩溃。
- 对隔离的原版 CWA 跑合成 EPUB/PDF 的上传、转换、查库和下载闭环；HTTP 替身不能替代这项证据。

退出：受控端到端与隔离原版 CWA 测试通过；上传返回 200 但未入库、同名多候选、响应丢失后重启均不误报成功或重复提交。没有原版 CWA 运行条件时标注 P3 部分完成，继续可独立执行的 P4 工作，不把模拟结果写成集成完成。

## P4：资源门槛、打包与操作文档

读取：内存预算、验收、运维设计。

- 按规定负载测量 RSS、容器内存、goroutine、FD 和文件体积增长影响。
- 在 128 MiB 容器内验证大文件、慢连接、取消、队列积压和重启。
- 修复资源泄漏和无界分配，再固定发布默认配置。
- 构建 Linux amd64/arm64 二进制与非 root 精简镜像。
- 提供原生 MCPHub command/args/env 配置与可选 HTTP/Docker Compose 示例；只用占位符。
- 记录实际配置键、运行命令、升级、备份、恢复和故障排查。
- 写入真实 benchmark 摘要，不复制目标数字冒充成绩。
- 对依赖和产物生成必要的许可证说明。

退出：本地交付物可复现、对应架构的资源门槛有证据；没有 arm64 实测时单独标注。尚无目标实例凭据时，可交付“本地验证完成、真实接入待测”，不能宣布全项目验收完成。

## P5：目标实例验收

需要操作者提供或在本地安全配置：CWA 版本/地址/服务账号、转换规则、可用书源账号、MCPHub 接入位置和文件接口地址。

- 不把这些资料写进公开仓库。
- 先执行只读兼容性探测；记录 CWA 与 MCPHub 实际版本。
- 取得真实环境测试授权后，用合成测试书完成上传、转换与下载。
- 验证 MCPHub initialize/tools/list/tools/call 和第一个真实 Agent 的文件能力。
- 验证设备离线后任务继续，另一设备可查同一任务并取书。
- 检查实际内存、Cloudflare 通路限制、CWA 重复处理设置。
- 对未通过项记录明确证据和边界，不修改 CWA 以绕过验收。

退出：验收矩阵通过，实际版本和资源报告齐全，操作者能按文档独立复现。

## 工作量参考

熟悉 Go 的开发者，受控环境内的基础闭环约 3–5 人天，含故障恢复、资源测试和交付约 6–10 人天。外部站点账号问题与真实环境等待另计。这是规划估计，不是承诺或进度完成度。

优先交付顺序固定为：资源与依赖风险 → 读取和搜索 → 单文件闭环 → 恢复与回收 → 资源门槛 → 真实环境。分块续传、通用格式解析、管理 UI 和扩展书源均不进入首版。
