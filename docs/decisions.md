# 决策记录

本页只记录已选方向及原因。实施细节链接到 plan，不在这里维护第二份规范。实现与验证状态在 plan/README.md 和 docs/validation.md。

## D01：Go 单进程

已接受。用户不习惯 Python，并要求常驻内存足够小。Go 能直接复用 heartleo/zlib 核心库，并将 MCP、HTTP 文件接口和任务 worker 放在同一进程。

替代方案：Python/Node 封装、CLI-to-MCP 桥接、多服务工作流。当前不采用，因为会增加运行依赖或链路。Go 的内存优势仍需实测，不能只凭语言选择宣布达标。

实施：[技术栈与内存](../plan/02-stack-and-memory.md)。

## D02：bbolt 只保存业务状态

已接受。单用户、单实例，需求是持久任务与索引，不需要外部数据库或 ORM。bbolt 是纯 Go 嵌入式 KV，适合该范围。

代价：mmap、单写事务、历史保留和数据库体积需要管理。所有书籍保存在 CWA，数据库不存正文。资源测试若发现确实不适用，再以证据修改决策。

## D03：原版 CWA，HTTP 边界

已接受。不分叉 CWA，不替换镜像内部脚本，不直接写其数据库；不额外运行 Calibre 转换器。通过现有 OPDS、网页上传和下载接口对接。

代价：没有可靠的逐次上传到最终书籍 ID 的任务 API，需要结果核对和歧义状态。ready 的定义是 CWA 中所需格式可交付。

实施：[CWA 集成](../plan/04-cwa-integration.md)。

## D04：中文优先，译本隔离退出首版

已接受。最新用户要求替代早期译本方案。默认优先中文，必要时才找其他语言；同一语言层内优先 CWA。

不再改书名、注入任务标签或开发译者/版次身份系统。CWA 的现有重复处理属于其自身配置，不由本项目重写。

实施：[范围](../plan/00-scope.md)。

## D05：MCP 控制，HTTP 传文件

已接受。MCP 只传小型结构化数据；同一程序提供短期授权上传和 CWA 下载转发，避免 base64 占用上下文与内存。

代价：Agent 必须能够读写本地文件、发 HTTP 请求；只有 MCP 调用能力的客户端不能自动获得本机文件能力。MCPHub 与文件接口的网络可达性都要验收。

实施：[接口契约](../plan/03-contracts.md)。

## D06：任务独立于传输会话

已接受。后台任务在持久化后继续执行；MCPHub 重连或设备离线不影响任务。服务通过 Streamable HTTP 常驻运行，不按设备启动独立业务进程。

不使用请求超时作为下载任务生命周期，不把长时间 CWA 转换塞进一次阻塞工具调用。

## D07：文档先交接，应用实现由后续 Agent 完成

已接受。初始化只创建公开仓库、规划和文档。后续 Agent 从 P0 开始实现，不把样例、假设和源码研究当成已经运行的产品。

## D08：首版单文件传输与单一完成格式

文档复核后收敛。首版使用流式整文件 PUT，自动校验并入队；不实现自定义分块、偏移、complete 和 Range 续传。失败从头传输，已接收文件的后台任务继续；对应代理限制在部署时明确校验。

每个任务只等待一个 required_format，额外保留格式不作为完成门槛。这样保留完整闭环和低内存约束，同时减少首版协议及恢复状态。需要大文件续传或多格式同步等待时，再用实际需求扩展。

实施：[接口契约](../plan/03-contracts.md)、[CWA 集成](../plan/04-cwa-integration.md)。

后续更改决策时：说明触发证据、影响范围和迁移代价，更新所属规范。边界重大变化需要用户的新指令，而不是自行扩大项目。

## D09：书源核心的最小有界补丁与 EAPI 通路

固定书源核心的元数据接口缺少 context，内部读取无项目大小上限。通过公开
HTTP client/context 注入修正，保留 MIT 许可证与改动清单；不使用反射或后台
超时包装。HTTP 层限制压缩前/后响应、重定向与实际取消；数组解码上限 50。

首版只启用已验证 EAPI 和已有合法会话；遇到 challenge 返回人工验证，不执行
上游挑战求解。未引入额外书源或 CWA 修改。见 [PATCHES](../third_party/zlib/PATCHES.md)、[运行文档](operations.md)。
